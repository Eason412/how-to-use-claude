# 链路与边界

## 角色与三类流量

机场提供入口节点；VPS 可运行自建代理或作中转；最终出口可以是固定 ISP 或用户指定的其他已验证出口。不要求每条链都包含三者。

| 范围 | 路径原则 | 故障要求 |
|---|---|---|
| 指定受保护流量 | 经本次选定链到期望最终出口 | 拒绝，不改走其他出口 |
| 普通代理流量 | 用户选择的机场或自建代理 | 不无故依赖固定出口；共享入口坏时可能同受影响 |
| 国内／局域网例外 | 明确批准的直连规则 | 不被代理故障无故阻断 |

可选拓扑包括设备→VPS→目标、设备→VPS→固定 ISP→目标、设备→机场→VPS→固定 ISP→目标。选哪一种由需求、可达性与验证决定，不能用供应商名字或历史方案决定。使用者常用的某个网络（如公司网）到 VPS 整体受限、换协议也无效时，属于结构问题：第一段改用在该网络下实测快的机场节点接到 VPS，最终出口不变。

向用户说明三个不同地址：客户端连接的服务器地址、中转对外连接最终代理时的来源、目标网站看到的最终出口。Reserved／浮动 IP 的出站限制见 [地址与资源](digitalocean.md#地址与资源)；客户端首页 IP 只代表该检测请求。

## 引用与协议

检查每级的实际 server、协议、认证与前置节点引用，无循环、无缺失。业务策略使用稳定内部名，不依赖订阅显示名。受保护策略只能包含合格出口或拒绝；备用入口也需满足同一最终出口约束，不自动加入旧链。

分清应用协议、代理协议和外层传输。HTTPS 应用可以经过 HTTP CONNECT、SOCKS 或其他代理；外层 HY2／QUIC 使用 UDP 不代表目标应用也使用 UDP，外层 TCP 也不等于“对某应用更兼容”。各段能否承载目标 TCP／UDP须分别验证。

标准 HTTP CONNECT 代理只承载目标 TCP；除非产品与客户端另有明确支持，不假定可转发 UDP。针对受保护的应用 UDP 明确拒绝或使用已验收路径；不要全局封 UDP 误伤 HY2 外层、普通应用与通话。SOCKS 协议能力不等于供应商开放对应能力。

设备→VPS 加密不意味着 VPS→HTTP 出口代理的认证也加密。HTTPS 网站内容有自己的 TLS，代理认证所在段另查；不要通过关闭验证修复导入问题。保留 VPS 是否必要，还取决于上游来源限制、认证传输和其他服务，不只看最终 IP。

## 流量识别与旁路

单靠域名不能同时保证所有未知受保护应用请求都固定，又让其他未知请求走普通代理。raw-IP、共享 CDN、helper、QUIC／STUN与IPv6都可能超出域名清单。

完整应用范围的受控入口、系统级兜底与授权边界见 [应用故障保护](egress-app-protection.md#范围与取舍)；其他客户端能力按 [跨客户端适配](import-export.md#跨客户端适配) 确认。

普通规则可能被全局／直连模式绕过，TUN 不是 kill switch，固定入站只约束进入它的连接；mode 与入口故障按 [验收矩阵](egress-validation.md#最小验收矩阵) 隔离验证。

### 整应用固定与例外顺序

只有用户接受该应用的其他业务也走固定出口时，才将整个浏览器等应用纳入范围。可采用：受保护域名及其 UDP 处理 → 明确国内域名／LAN 例外 → 整应用固定及 UDP 处理 → 其他应用国内规则 → 普通代理。宽泛国内 IP 兜底不得抢先覆盖保护范围。

整浏览器范围、helper 与 native host 的取舍见 [应用故障保护](egress-app-protection.md#范围与取舍)。

## DNS 与 IPv6

区分目标解析、入口节点解析、DNS 请求出站和最终代理远端解析。入口域名 bootstrap 不应循环依赖尚未解析的自身。DNS 关闭 AAAA 不代表系统、字面 IPv6 或远端代理都不使用 IPv6。固定 IPv4 要求需验证 IPv6 被拒绝或实际经过另行批准的路径。

原生参数与版本行为读 [客户端适配](import-export.md#跨客户端适配)。
