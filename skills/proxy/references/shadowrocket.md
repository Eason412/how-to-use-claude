# Shadowrocket 适配

仅在目标设备确实使用 Shadowrocket 时读取。桌面端通过不等于手机通过；导入节点不等于分流生效。

## 两类数据与命名

首页管理节点和订阅；“配置”页管理规则及策略组。两类数据分别核对，删除 .conf 不会自动删除首页旧节点，订阅更新也不保证整份规则保持。

先定义用户实际需要的短名称，再生成内部引用。每一条引用必须逐字匹配其引用对象的实际保存名称；订阅备注、节点名、策略组名不必同名。按实际保存值核验，不按输入成功回执判断。给用户解释“选哪份使用方案”，不要让其每次访问不同网站时手动拼链。若采用自动分流，需要真正核实规则与组绑定；不能仅凭设计就说无需选择。

## 导入与读回

1. 用受支持的私有文件传输／导入方式，保存旧配置可恢复副本。下载被阻止时不说已备份，也不绕过浏览器限制；使用已有合法副本或说明恢复缺口。
2. 节点和原生 .conf 分别导入。Clash YAML 兼容导入不能假定全部字段保留；节点二维码也不代表完整规则。
3. 逐级核对“代理通过”、前置节点存在、认证、SNI、ALPN、TLS 验证与证书指纹。转换丢字段时修正目标配置，不靠关闭证书校验使它通过。
4. 核对“配置”页使用标记、默认标记及全局路由是否为“配置”；看清两种标记，不把文件存在或默认等同于当前启用。
5. 核对配置的实际策略组成员、订阅名称与规则动作。未解析组、名字截断、重名副本先修正再连通测试。
6. 用手机本身的公共诊断请求验证出口；用规则测试／允许的请求区分普通代理、固定出口与国内直连。禁止测试真实服务时只保留对应未验证项。
7. 新方案验收后按授权分别删除旧配置和旧订阅／节点。删除前核对精确名称、内容、日期、依赖和使用状态，保留最小回退。

配置语法参考可查 [LOWERTOP 手册](https://github.com/LOWERTOP/Shadowrocket)，它是非官方社区资料。close-if-proxy-chain-missing、udp-policy-not-supported-behaviour 等只能作为待验证候选；字段存在不证明认证失败、超时、空组、IPv6 都按要求拒绝。全局 UDP 行为可能影响普通应用，不能默认复制桌面局部拒绝规则。

## iPhone 镜像与传输卡点

只使用当前授权的 UI 工具。每次依据新界面定位，不把某次坐标固化。输入后查看实际文字和保存结果；连续两次丢字、粘贴无效或文件选择失败即停，核对焦点、输入法与工具能力，不反复盲输。

本地 Wi-Fi 上传是可选的已使用路径，不是唯一方式：从手机页面读取当次地址，服务通常需要页面保持前台；浏览器展示缓存表不证明服务仍在线。同名上传可能产生编号副本，按内容／日期辨认。文件选择器必须确认真实选中文件后再打开；本地桌面环境可用系统“前往文件夹”定位完整路径，但不能预设其他平台支持。

文本输入仍不可靠时，只让用户完成那一个具体字段，其余不依赖输入的已授权工作继续。不要把未保存的半截名称写入完成结论。传输结束关闭临时上传服务，恢复本次改动的剪贴板并清理含凭证临时副本。

## 交付

配置名应描述路径，例如“自建固定出口”和“机场”，不因追求短名字让 VPS 裸出口与固定 ISP 混淆。只列实际已验收方案、怎么选择和未完成项；手机未实测不宣称完成，不同时扩展到未授权的 iPad。
