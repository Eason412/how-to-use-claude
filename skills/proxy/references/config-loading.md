# 配置加载与应用验收

用于给应用加入现有固定出口，或排查“文件已改、保存成功，但连接仍走旧出口”。目标是让持久源、最终规则和应用新连接一致。

## 找到实际生成链

先定位当前活动配置及其绑定的全局／专属 merge、script、rules，再确认运行内核、配置路径和控制器。服务模式与普通模式可能使用不同路径，不能把失效 socket 当成内核停机。

对照“持久源 → 扩展合并与脚本 → 生成配置 → 内核规则 → 应用连接”，找到目标规则最先消失或改变的位置：

| 证据 | 下一步 |
|---|---|
| 活动配置不是已修改的配置 | 核对当前 UID 和绑定；先定位活动配置，不盲改无关历史备份 |
| 源中有规则，生成结果中没有 | 查脚本的过滤、白名单重建、去重与排序；例如过滤全部 `PROCESS-NAME` 后只重建部分应用，会丢掉新增规则 |
| 生成结果正确，内核没有 | 查实际加载路径、加载回执与解析错误；不要继续重复添加规则 |
| 内核有规则，连接仍走默认组 | 核对连接创建时间、实际进程名／路径、接管入口、模式和前置规则 |
| 只加载 UDP 拒绝，缺少 TCP 固定路由 | 分别追踪两类规则经过扩展后的结果；不能用“有应用规则”代替完整验证 |

修改拥有该策略的持久源或受支持扩展（含本机配额适配器读取的权威源 YAML 与在用备用配置脚本），不只改会被订阅刷新覆盖的下载缓存。自有配置负责链和规则，采用客户端支持的 provider／扩展。生成文件和系统服务运行副本用于比对，不作为长期修复位置；否则下次生成会覆盖修改。应用包内 helper 与独立子进程按实际路径确认，不用进程名包含某个短词来归属连接。

## 检查规则与加载入口

生成后的规则要同时检查内容和顺序。若要求应用全部公网流量固定出口，进程规则不能排在会提前命中的公网直连白名单、其他域名策略或 `MATCH` 后；需要保留的本机／内网通信单独核对，不照抄另一个应用的例外。具体语法与包路径匹配见 [Clash Verge 适配](clash-verge.md)。

涉及扩展脚本时，先在隔离副本上用实际输入和已确认的扩展顺序检查最终输出：新增规则是否保留、优先级是否正确、原有受保护规则和入口是否保留。只查 JavaScript 语法不能证明生成行为正确。

按安装版本核实操作入口对应下载、保存、重新生成、加载还是重启；给出已核实的操作路径。

服务拒绝加载目录之外的文件时，定位该客户端受支持的生成／同步入口，不扩大 `SAFE_PATHS`、改变系统目录权限或猜测写接口。控制 API 的临时加载不代表下次启动仍有效。只筛选本次相关连接，旧连接不默认断开；重启、切订阅和清空连接沿用 [连接保护](connection-safety.md)。

## 按证据交付

- **文件已更新**：只说明持久源修改完成。
- **规则已加载**：内核读回包含预期路由与拒绝规则，且顺序符合范围；总条数增加本身不够。
- **应用连接已命中**：记录加载后的目标应用新连接、协议、命中规则和固定节点；没有活动连接时标为尚未取得连接证据，不判成功或失败。
- **公网出口已核实**：通过已确认绑定同一最终节点的入口查询公网 IP，并与预期地址、地区对照。标明这是该入口的探测结果还是应用自身请求；节点名称或连接链不能单独证明地理位置。

TCP 命中固定节点、UDP 拒绝计数，均不单独证明全部流量无泄漏、代理退出后仍阻断或其他应用也受保护。报告本次实际验证的范围；要验证故障保护时按 [固定出口验收](egress-validation.md) 选相应检查，不在当前会话链路上做断线测试。

连续失败时按 [分层排查](troubleshooting.md#地址协议和线路对照) 处理。

## 订阅更新

更新前保存当前成员与配置，连接影响按 [连接保护](connection-safety.md) 确认：
1. 核对源订阅与当前使用配置是否同一数据来源；inline 副本不自动跟随源更新。
2. 更新后沿“源 → provider → 组 → 链式引用 → 规则 → 运行态”逐级检查；名称精确对应、筛选成员非空、无循环或混入其他供应商。
3. 分辨空组、节点缺失、缓存过期、认证失效、解析拒绝及旧配置继续运行，不把更新提示当作生效证据。
4. 检查相关 DNS 合并、专口、mode／TUN 与持久源；同时核对应用显式入口与候选配置的监听、绑定目标。缺少固定入口导致应用拒绝连接时，不据此认定远端出口故障，也不撤销断线保护来修配置不匹配。用公共小请求验证需要保持的出口与普通分支。
5. 失败拒绝与回退见 [链路与边界](egress-chain.md#引用与协议) 和 [回退与清理](egress-validation.md#回退与清理)。
