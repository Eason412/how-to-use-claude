# macOS 应用断线保护

## 适用范围

内核退出、TUN 关闭或应用组件不认显式代理时，代理规则不再起作用。需要“断了也不直连”的整进程限制时，用按程序过滤的出站防火墙（LuLu、Little Snitch 等）补一层。它不替代分流，也识别不了供应商自行更换的出口 IP。PF 只能按用户／组匹配，不能按可执行文件区分。

## 结构

受保护程序只经本机固定入口联网，防火墙对这些程序拒绝全部非本机连接，本机回环照常放行。前提是程序的主要流量已走显式 loopback 入口（浏览器策略、启动参数、自身代理设置）；只靠 TUN 的程序被拒后无法联网，因为 fake-IP 下过滤器看到的是非本机地址。

- 浏览器与固定出口应用分入口：应用入口硬绑定最终出口；浏览器入口可带专属规则，让明确的国内名单直连、其余固定。改浏览器名单不影响应用入口。
- 过滤本机地址只防“程序改用其他本机代理端口”，代价是阻断 IDE、插件、native host 的本机通信。现场没有这条路径时保留回环放行；确需防范时，用精确“地址＋端口”只拒绝那个端口。
- 代理内核自身必须放行。

## LuLu 设置

按安装版本核对界面与[规则匹配源码](https://github.com/objective-see/LuLu/blob/v4.5.1/LuLu/Extension/Rules.m)。

- 签名程序按签名 ID 建规则，更新、移动后仍有效；未签名按路径。
- 匹配按具体程度：地址与端口都精确 > 一项通配 > 全通配；同一层级中程序自身规则覆盖全局与目录规则。已有“全部允许”的程序规则时再加“全部拒绝”属于同层冲突，先删旧规则。
- 初始设置：放行 Apple 程序；不勾“放行已安装程序”，否则会给目标程序生成全部允许；关闭“放行 DNS 流量”，否则受保护程序可直接发 UDP 53；保留 localhost 放行。
- 被动模式设为允许新连接、不创建规则，其他软件照常联网且不弹窗。初始设置完成前出现的询问弹窗，对非目标程序选允许。
- 规则对象：浏览器主程序与负责网络的 helper，Electron 应用主程序与 `<App> Helper`，命令行客户端二进制。渲染、GPU 进程不直接联网。包内其他组件（更新器、MCP 服务、native host）需要直接联网时不加拒绝规则，由代理的进程路径规则固定其出口。
- 网络扩展由用户在系统设置批准。生效后读取规则文件（keyed archive），逐条核对 key、地址、端口与动作，不只看界面。
- 给当前助手所依赖的程序加规则放在最后，先确认其流量已全部走显式入口，并告诉用户出现失联时如何删除该规则。

## Electron 桌面应用入口

- 启动参数：`--proxy-server=http://127.0.0.1:PORT`、`--force-webrtc-ip-handling-policy=disable_non_proxied_udp`、`--disable-quic`；用 `open --env` 把 `HTTP(S)_PROXY` 传给认这些变量的组件。
- 参数只在应用未运行时生效。开机自启、URL scheme、原程序坞图标都会不带参数启动：关闭开机自启，用启动器替换常用图标；启动器检查已有实例是否带参数，未带时提示先退出，不叠加启动。
- 主进程的原生更新器（Squirrel、NSURLSession）不遵循 Chromium 代理参数，被拒后自动更新可能失败，改为手动更新并如实报告。
- 虚拟机类功能由系统虚拟化进程联网，不在应用规则内，另行评估。
- 用 osacompile 生成的启动器，`Assets.car` 与 `CFBundleIconName` 优先于 `applet.icns`；换图标时删除二者、重新 ad-hoc 签名并刷新 LaunchServices。

## 验收

- 正常态：各入口的新连接经预期 chain，受保护程序在代理控制器里没有 TUN 旁路连接。
- 忘记入口：不带参数启动应用，应无法加载，且控制器中该程序的 TUN 连接为 0。
- 内核完全退出、切到没有入口的配置：按 [应用故障保护](egress-app-protection.md) 的维护窗口要求测试，未测保留为未验证项。
