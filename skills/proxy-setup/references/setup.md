# 自建代理搭建

先复用符合需求的已有服务；只有确需新增且已获安装／变更授权才部署。共享 VPS 的其他服务、依赖和认证路由不是默认写集。

1. **选结构**：明确设备及客户端、普通与固定出口需求、可用网络和是否必须 TUN。代理型 SS／HY2 与路由型 VPN 的配置不同；目标客户端不支持的协议不因名字熟悉就选用。
2. **创建云资源**：如果还没有服务器且选择 DigitalOcean，先读 [创建流程](digitalocean-create.md)；其他云按其当前官方流程，创建完成后回到本页。不要把“云服务器已创建”当成代理已经部署。
3. **查服务器**：核实地址、管理与恢复入口、服务监听、CPU／可用内存／磁盘、云及主机防火墙。选未占用端口，不覆盖生产服务或释放现有端口。
4. **部署服务**：按当前项目安装规则和协议官方文档选受支持版本，使用独立服务与最小配置，设置认证和适当证书验证。凭证不进日志；记录本次文件、服务、规则及回退身份。只有所选架构需要时才配置转发和 NAT。
5. **连通验证**：先确认监听及服务日志，再用目标客户端支持的私有配置做有限测试，读回实际地址、协议、认证和 TLS 结果。临时开端口按 [防火墙流程](firewall.md)，不因失败放宽全网或关闭校验。
6. **接入与分流**：按 [导入流程](import-export.md) 在授权范围持久化并激活；需要固定出口时进入 [固定出口链路](egress-chain.md) 阶段，普通代理不自动添加固定 ISP。
7. **交付**：目标设备新连接实际成功、规则与出口符合要求才算可用；保留管理恢复能力、最小备份与服务定位，清理临时测试资源。速度与长期稳定性按实际测量范围报告。

## 选择协议与平台

本技能提供 [Hysteria2具体部署分支](hysteria2.md)，适合已确认客户端支持且实际网络允许所需 UDP 的方案；不把它作为所有客户端的固定答案。仅支持 TCP 或所选客户端不支持 HY2时，明确改选理由，按所选协议官方文档准备独立部署与验收步骤，不以临时端口测试代替完成部署。SS等其他协议目前没有本地逐步配方，不能假称已经全部覆盖。

Windows电脑读 [平台适配](windows.md)，macOS／Linux 按各自路径和权限处理；服务器步骤始终标明在Linux VPS执行。已有客户端就按能力适配，不为复用Mac配置要求用户更换操作系统或安装WSL。

每个阶段留“已选择／已创建／已部署／目标端已验收”中的实际状态与证据位置。最终交付包含服务定位、私有客户端配置、如何连接与查看流量、已测设备、恢复方式；阶段中断后从最后一个已确认状态继续，不重复购买或导入。

## 硬停止条件

预算、付款授权、协议可达性、证书验证能力、客户端字段或恢复入口任一项无法满足时，保持服务未启用，或停止本次独立服务并撤回临时规则；记录最后一个已确认阶段和恢复位置，等待用户决定。不得继续购买、反复重启、放宽证书校验或把失败方案交付成可用。
