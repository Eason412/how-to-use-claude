# 防火墙边界

## 先辨认“白名单”

| 用户目标 | 对应层 |
|---|---|
| 某网站不走代理 | 客户端分流规则 |
| 指定请求不得走普通出口 | 客户端拒绝／固定策略，必要时另定系统级边界 |
| 允许某来源连接 VPS | 云与主机防火墙的协议、端口、来源 |
| 出口代理允许某来源认证 | 供应商当前产品的认证设置 |
| 其他设备使用本机代理 | 监听地址、局域网访问与本机网络权限 |

不要用开放云端口替代 ISP 认证，也不要用网站控制台登录状态证明 SSH 可达。先读实际绑定、方向、协议、端口、来源 CIDR；TCP 和 UDP 同端口是不同规则。

## 安全修改与验证

读取服务监听及现用防火墙后端，不默认 UFW 开启，不同时重写多个后端。只处理用户范围内的精确条目；其他共用服务、SSH、已有 TCP／UDP规则保留。管理来源取服务器实际收到的新连接，不一定是浏览器查到的 IP。

修改 SSH 来源时先保留旧入口，用新来源建立第二条独立连接验证，再按授权收紧旧规则。IPv4 单来源为 /32，IPv6 为 /128；不为方便开放全网 SSH，不使用 flush/reset、盲目启用防火墙或改变默认策略作为排错。

云端多个防火墙的合并规则按供应商当前文档确认。无独立恢复入口时不要冒险改断管理路径。DigitalOcean 的控制台区别见 [供应商说明](digitalocean.md)。

## 临时握手与端口测试

1. 核实目标服务器、当前测试路径和服务端将看到的来源；重新确认目标 TCP／UDP 端口未被占用，不沿用旧出口地址。
2. 将规则身份（防火墙 ID、方向、协议、端口、来源、是否已存在）与测试进程／监听记录在本次私有状态中。已有等价规则不得记为“本次新增”并在收尾删除。
3. 仅在授权范围添加来源限制与临时服务；不重启生产代理、不更换客户端配置、不改无关规则。若必须影响现有链路且用户要求保持，先暂停。
4. 发一次或约定次数的受控握手，记录实际到达和结果。裸 TCP 握手只证明该来源到该地址端口当时可达，不证明代理认证、TLS、速度或最终出口。
5. 无论成功失败都执行清理：停止本次创建的进程，按精确身份删除本次新增规则，再独立读取监听与云规则确认不存在；比较其他规则与必要连接状态。
6. 操作中断后根据状态记录恢复清理，不能仅因删除按钮成功就称已恢复。没有清理回执则报告仍待核实项。

## 代理与控制口

HY2 外层需要 UDP，开 TCP 同号端口不能替代。代理服务仍需认证与适当证书验证，不因测试关闭。客户端控制器保持本地认证访问；本机 allow-lan、控制器或服务器私有管理端口不默认扩大到公网／局域网。

客户端退出后系统级拦截是独立方案，链路维护授权不自动包括部署守护进程或自动断网。只读规则检查只能报告已核对，不能说拒绝路径已实测。
