# 分流与验证

## 先分入口与路径

系统代理只影响遵循它的应用；TUN 接管范围依赖路由和客户端实现，不等于没有旁路。`curl --noproxy '*'` 只绕过显式代理，可能仍经过 TUN，不能称为物理网络直连。

按现场把请求分成普通代理、指定固定出口、国内／局域网直连及明确拒绝。用户没有要求固定出口或特定应用封锁时，不额外添加。需要固定出口时读 [链路边界](egress-chain.md)。

## 规则顺序

1. 明确需要保护或拒绝的请求优先，不能被宽泛国内 IP 规则提前放走。
2. 国内域名与局域网例外按用户要求保留；共享 CDN 不整段归为国内或某个应用。
3. 其他应用按普通国内规则和默认代理兜底。采用整应用固定策略时，规则顺序按固定出口参考，不套用普通分流模板。
4. 新建测试连接并读取命中规则和实际链；旧长连接可能保留原路径，不默认清空全部连接。

规则资源格式由客户端决定。Mihomo 的 MRS、GEOSITE、进程规则不能默认移植到其他客户端。远程规则需要确认可信来源、加载成功与更新语义；数量不是正确性证明。

## 验收边界

公共检测页只能证明那次请求的路径。连接错误不等于规则拒绝，要有命中或隔离上游的证据。不主动访问真实账号服务做阻断测试，使用合成域名、loopback 和允许的公共目标。

WebRTC 出现 VPS IP 可能是 HTTP 与 UDP 分流不同，不直接等于家庭 IP 泄漏。不能为修补一个检查页面就关闭所有 UDP、改变时区或浏览器指纹；针对性拒绝需考虑现有隧道和通话。
