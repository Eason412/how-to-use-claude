# 代理搭建与排障

先说明实际路径及影响范围，再完成用户要求的诊断或修改。机场是提供节点的订阅服务，VPS 是自建服务器，客户端负责接入与分流；这些角色不绑定品牌，也不必全部存在。

## 两个技能的分工

本技能负责资源创建、协议部署、客户端导入、普通分流、用量与运行维护；fixed-egress 负责最终出口设计、应用接入、失败保护和迁移验收。流程为“需求与资源 → VPS／代理部署 → 固定出口组合 → 应用接入 → 验收 → 持续维护”，按任务进入对应阶段，不强制重走已完成步骤。模型桥接内部配置仍由其专用技能处理；本流程识别并保护它作为连接依赖，不扩展写集。

## 工作流

1. **确定目标与现场**：区分诊断、搭建、分流、迁移；读取设备、客户端及内核版本、当前订阅、模式、TUN／系统代理、组选择与实际请求路径。文件、界面和运行态可能不同。
2. **定位故障层**：按症状读参考，检查输入和实现，再区分 DNS、规则、节点、协议、服务器、防火墙和上游。只读诊断到原因与建议为止，不自行修复。
3. **选择最小改动**：说明改变哪一段、不变哪一段。备份受影响源配置、扩展和引用映射；Unix含凭证文件 0600、目录 0700，Windows使用最小NTFS访问权限。实施已有授权内的改动，不重复索取已明确的许可；会影响用户要求保持的连接时暂停。
4. **持久化与验收**：改受支持的源配置或扩展，不只改运行时文件，也不直接改会被订阅更新覆盖的下载原文。生成后读回运行态，分别确认连接、规则命中和性能；跨设备单独验收。
5. **清理交付**：确认未被正式链路或当前会话引用后，停止本次临时进程、移除本次新增测试规则与无用文件；保留一份满足当前要求的回退版本和最小脱敏证据。报告实际结果、未验证项和回退位置，不展示流水账。

## 维护前置检查

任何改名、清缓存、升级、重载或服务操作前，先读 [运行维护](references/maintenance.md) 并识别当前会话的连接依赖。当前助手依赖的桥接、代理或隧道不能在该链路内停止；这项约束不以用户另说“保持连接”为前提。固定入口与应用策略的一致性另按 fixed-egress 验收。

- 从零部署自建服务：[搭建流程](references/setup.md)。

## 边界

凭证、完整订阅 URL、控制器 secret 和私人配置不进入 Skill、报告、Git 或公共转换网站。链路测试默认公共诊断目标或本地模拟，不主动访问 Claude／Anthropic 或其他账号服务；明确禁测时直连与代理均不访问。不顺带清登录状态、改指纹、付款或开放服务。

规则模式、系统代理和 TUN 是不同层；首页 IP、HTTP 200、节点延迟和浏览器错误均不能单独证明应用路径。控制器保持本地认证访问，只筛选本次目标的连接，不输出全部浏览活动。
