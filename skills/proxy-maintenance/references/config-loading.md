# 配置加载与应用验收

用于给应用加入现有固定出口，或排查“文件已改、保存成功，但连接仍走旧出口”。目标是让持久源、最终规则和应用新连接一致；不靠反复刷新或重启猜测原因。

## 找到实际生成链

先定位当前活动配置及其绑定的全局／专属 merge、script、rules，再确认运行内核、配置路径和控制器。旧记录只作定位线索；服务模式与普通模式可能使用不同路径，不能把失效 socket 当成内核停机。

对照“持久源 → 扩展合并与脚本 → 生成配置 → 内核规则 → 应用连接”，找到目标规则最先消失或改变的位置：

| 证据 | 下一步 |
|---|---|
| 活动配置不是已修改的配置 | 核对当前 UID 和绑定；不要顺手同步所有备用文件 |
| 源中有规则，生成结果中没有 | 查脚本的过滤、白名单重建、去重与排序；例如过滤全部 `PROCESS-NAME` 后只重建部分应用，会丢掉新增规则 |
| 生成结果正确，内核没有 | 查实际加载路径、加载回执与解析错误；不要继续重复添加规则 |
| 内核有规则，连接仍走默认组 | 核对连接创建时间、实际进程名／路径、接管入口、模式和前置规则 |
| 只加载 UDP 拒绝，缺少 TCP 固定路由 | 分别追踪两类规则经过扩展后的结果；不能用“有应用规则”代替完整验证 |

修改拥有该策略的持久源。生成文件和系统服务运行副本用于比对，不作为长期修复位置；否则下次生成会覆盖修改。应用包内 helper 与独立子进程按实际路径确认，不用进程名包含某个短词来归属连接。

## 检查规则与加载入口

生成后的规则要同时检查内容和顺序。若要求应用全部公网流量固定出口，进程规则不能排在会提前命中的公网直连白名单、其他域名策略或 `MATCH` 后；需要保留的本机／内网通信单独核对，不照抄另一个应用的例外。具体语法与包路径匹配见 [Clash Verge 适配](../../proxy-setup/references/clash-verge.md)。

涉及扩展脚本时，先在隔离副本上用实际输入和已确认的扩展顺序检查最终输出：新增规则是否保留、优先级是否正确、原有受保护规则和入口是否保留。只查 JavaScript 语法不能证明生成行为正确。

区分下载远程订阅、保存源配置、重新生成、加载内核和重启核心。给用户操作步骤前，按安装版本的源码、文档或实际 UI 核实该入口做什么；不根据刷新箭头、火焰等图标猜行为，也不保证重复点击活动卡片一定重载。可用工具执行已授权步骤时完成操作并读回结果；需用户点击时给出已核实的一条路径。

服务拒绝加载目录之外的文件时，定位该客户端受支持的生成／同步入口，不扩大 `SAFE_PATHS`、改变系统目录权限或猜测写接口。重启、切订阅和清空连接可能影响当前会话，沿用 [连接保护](connection-safety.md)，不能作为默认补救。

## 按证据交付

- **文件已更新**：只说明持久源修改完成。
- **规则已加载**：内核读回包含预期路由与拒绝规则，且顺序符合范围；总条数增加本身不够。
- **应用连接已命中**：记录加载后的目标应用新连接、协议、命中规则和固定节点；没有活动连接时标为尚未取得连接证据，不判成功或失败。
- **公网出口已核实**：通过已确认绑定同一最终节点的入口查询公网 IP，并与预期地址、地区对照。标明这是该入口的探测结果还是应用自身请求；节点名称或连接链不能单独证明地理位置。

TCP 命中固定节点、UDP 拒绝计数，均不单独证明全部流量无泄漏、代理退出后仍阻断或其他应用也受保护。报告本次实际验证的范围；要验证故障保护时按 [固定出口验收](../../proxy-setup/references/egress-validation.md) 选相应检查，不在当前会话链路上做断线测试。

同一目标连续两次未生效，按 [分层排查](troubleshooting.md) 停下复核被证伪的假设和引入问题的决定，再选择下一步；不要换一个按钮让用户再试。
