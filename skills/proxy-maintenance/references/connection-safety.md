# 运行维护

用于代理、固定出口及其连接依赖的日常维护。先区分显示改名、配置迁移、清理、升级与故障恢复；只处理本次授权范围。后台开关表示许可，不等于当前占用；解释器名称不能用来判断服务用途。用启动配置、实际进程和监听建立对应关系，只读取必要字段，不输出凭据或个人文件正文。

先建立最小依赖图：当前助手／浏览器／命令行 → 本机桥接或专口 → 代理内核／隧道 → 远端入口与最终出口；管理与恢复通道也需确认是否经过被维护链路。建立 VPS 时未上线的新服务与承载现有会话的服务必须分开处理。

## 当前连接保护

任何操作只要涉及 LaunchAgent、守护进程、解释器、包缓存、代理或隧道，先确定当前助手、浏览器和工具是否依赖它。用途不能确认时按连接依赖保护。改名、缓存清理和一般整理的授权，不等于允许中断当前连接。

- 当前会话依赖的服务禁止执行 bootout、kickstart -k、kill、brew services restart 或具有等效效果的操作；不可先停再试。涉及由其他工具管理的桥接时，先读该工具自己的维护说明。
- 名称整理优先保留运行实例，只准备可回退的启动元数据，待用户下一次正常登录加载。明确“已准备”和“界面已生效”的区别。不要为了立刻显示名称强制重启服务。
- 包装启动入口时保留原参数、环境、工作目录、调度、Label 和凭据边界；使用 exec 保持信号/进程语义，拒绝二次拼接未转义参数。先备份、检查真实 shebang/换行和包装命令与原命令等价，再原子写入；shell 语法检查可能把含字面反斜杠 n 的整行当注释，不能单独证明入口可执行；不能通过运行第二份生产服务来测试。
- 只有任务本身确需停机，且有独立于被修改链路的恢复通道与明确维护窗口时，才另行处理；不要把“有备份”当作可自动恢复。

## 清理与验证

缓存按实际用途划分，模型、运行依赖、项目虚拟环境、网盘数据和网站存储不因位于缓存目录就删除。优先包管理器原生清理，遵守占用锁，不用 force 绕过；被持续服务占用且没有安全维护条件时保留。报告工具统计与实际释放空间的区别。

应用卸载保留用户文档和网盘文件。失效启动引用与应用本体分别核验；系统列表可能保留历史登记，不为消除显示条目重置整套后台数据库。UI 操作使用允许的 UI 工具。

写入完成不等于服务恢复。验收分别核对持久化配置、运行实例、监听及相关功能；无需重启的维护前后应保持受保护进程身份不变。回退须检查恢复命令返回值和恢复后健康状态，只有文件恢复时只能报告“文件已恢复”。多步 shell 显式检查每个必要步骤，不能用末条健康查询的成功掩盖前面部署失败；健康查询必须针对被修改的服务。任何失败都保留退出码和脱敏错误，不在未检查时打印“已恢复”。

同一目标连续失败或出现连接中断，停止扩大修改，先查自己引入的依赖变化与中断动作。将本地时间线和证据留在私有项目记录；本技能只存通用方法，不收录个人路径、地址、账号或用量。
