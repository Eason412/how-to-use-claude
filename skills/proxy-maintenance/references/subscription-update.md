# 订阅更新

更新前保存当前成员与配置，先确认更新／激活是否主动关闭现有连接；当前会话依赖的链路不原地做断线测试，在授权内操作：
1. 核对源订阅与当前使用配置是否同一数据来源；inline 副本不自动跟随源更新。
2. 更新后沿“源 → provider → 组 → 链式引用 → 规则 → 运行态”逐级检查；名称精确对应、筛选成员非空、无循环或混入其他供应商。
3. 分辨空组、节点缺失、缓存过期、认证失效、解析拒绝及旧配置继续运行，不把更新提示当作生效证据。
4. 检查相关 DNS 合并、专口、mode／TUN 与持久源；用公共小请求验证需要保持的出口与普通分支。
5. 失败则保持合格旧状态或按授权回退；不把受保护范围降级到 DIRECT／裸机场。只有源已更新但运行态未读回，不能交付“刷新不会丢”。
