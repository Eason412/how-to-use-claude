# 月用量订阅卡片

适用于在现有 Clash Verge 订阅卡片中显示自建 VPS 月用量，并支持手动或定期刷新。先确认统计对象、额度、计量方向、周期和允许误差；不要默认同时监控所有上游。

## 计量口径与连续性

优先供应商 API 的实际用量；无合适 API 且用户接受估算时，可用 vnStat 持久化公网接口 TX/RX。接口统计包含该接口的其他服务流量，不等于某个代理或应用的用量。核对 GB/GiB、计费时区、自然月或账期、免费流量与共享额度；分子和额度必须属于同一范围。仅出站计费时不要累加入站，不能把本机估算称为官方账单。

历史未采集流量无法倒推。用官方快照补起点时，记录其数据实际截止时间 `t0`、当期用量 `B`，以及同一时刻、同一计数序列的本地读数 `C0`；当期估算为 `B + C(t) - C0`。不能直接把已含历史流量的本地月总量再加到 `B`。若时间或口径无法对齐，明确记录缺口或重叠及估算依据；误差不被接受时，只展示已采集期间，不声称完整月用量。

持久化账期标识、基线、计数来源/接口、计数序列标识及最后有效样本和源时间戳；进程重启不能重设基线。新账期不沿用旧 `B`，须取得属于新账期的有效数据；没有当期记录不能自动解释为零。同账期计数下降或数据库重建，暂停发布新值并重新校准，不能用归零或截断负差掩盖断档。按数据源的实际截止时间判断新鲜度，不能把 SSH 成功时间当成计数更新时间。vnStat 的落盘周期会造成读取延迟，调整账期或时区也不会重算已有数据。

## 接入顺序

1. **保存回退点。** 备份目标卡片的原类型、URL、UID、文件名、完整 `option`、节点选择、订阅原文及所有扩展内容/引用，记录活动订阅和运行配置摘要。含密材料留在权限收紧的私有项目目录，Skill 只存通用方法。
2. **建立可靠采集。** 先检查 VPS CPU/内存/磁盘与现有服务，再部署轻量计数服务；安装后实测 RSS 和 CPU，不套用别台机器数字。确认持久化和至少一个有效样本后，再接入卡片；无需为月计量部署大型监控栈。
3. **先验收适配器。** 单机可用本地回环 HTTP 服务，经已有 SSH 读取 VPS 计数。只绑定回环地址，使用不可猜测的访问凭证，校验 Host，拒绝非预期的浏览器 Origin（原生客户端可能无 Origin），不开宽泛 CORS；不记录完整 URL、订阅正文或凭证。SSH 保留主机校验，采集命令固定为只读，不从 HTTP 参数拼接命令。轮询与订阅请求分离，设置读取超时；状态原子写入，断网或并发请求不能覆盖最后有效样本。
4. **保持订阅内容。** 适配器以私密原文为权威源，响应正文保持一致；用 `subscription-userinfo` 头返回非负整数字节 `upload=<bytes>; download=<bytes>; total=<bytes>`。单方向计量时另一字段填零，并记录方向映射；月额度重置不等于订阅到期，不伪造 `expire`。数据缺失、过期或计数异常时返回非成功状态，保留客户端上一份有效配置和用量；不要以空节点、零用量或新鲜时间戳掩盖失败。
5. **迁移目标卡片。** 通过受支持的编辑入口将同一卡片接到适配器，保留 UID、文件名和 `merge/script/rules/proxies/groups` 引用，不只改运行时文件。先读完整 `option` 再合并所需字段：编辑接口可能整项替换 `option`，而刷新接口可能按字段合并，两者不能混用。保存后读回持久化数据核对引用，再继续刷新。
6. **刷新并核对运行态。** 只操作目标卡片，实际点击箭头，确认显示用量、正文、扩展、节点选择、原出口和受保护监听。活动订阅刷新可能触发配置校验与重载；发生并发校验错误时先查持久化与运行态，再单独重试，不连续更新所有订阅。
7. **设置自动更新。** 分开确定服务端采样、适配器轮询、客户端刷新和过期阈值，说明手动刷新读取的是最近有效缓存。Clash Verge Rev v2.5.7 中 `option.update_interval` 为分钟，`profile-update-interval` 响应头为小时，已有 option 值优先；还需启用自动更新且间隔大于零。遵循安装版本的最小间隔；每日更新可作为月用量显示的起点，不把它写成通用硬限制。保存后重新打开设置核对，应用重启持久性只在不承载当前会话且有维护窗口时验证，否则注明未测。
8. **完成验收与回退记录。** 用隔离样本覆盖计量方向、基线差值、跨月、计数回退、过期和 HTTP 正文/元数据；实机检查正常刷新、失败时保留配置及资源占用；服务重启恢复按 [运行维护](connection-safety.md) 判断能否测试，不为完成清单而中断当前链路。模拟跨月通过与实际跨月运行分开报告；未真实等待自动刷新周期须注明。回退按固定顺序：暂停目标卡片自动更新并等在途请求结束 → 恢复原类型、源配置和完整元数据/扩展（自动更新暂时保持关闭） → 确认原配置及出口生效 → 恢复原更新策略 → 停用本次适配器。原卡片不一定是本地类型，不一律改成 local；只移除本次独占且不再需要的采集组件。

交付记录保留实际采集起点、数据截止时间、更新延迟、估算缺口、验证结果和回退位置。用户地址、SSH 标识、真实额度/用量、私人路径及账号信息不复制到 Skill。
